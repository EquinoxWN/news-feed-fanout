builds shared the machine during these runs, so timings vary between runs (see Analyze).

## Analyze

- The write cost is set by the follower distribution, not by the number of posts: 3 of 2,003 posts
  (0.15%) caused 3,489,355 of 3,536,366 writes (98.7%). This is the measured reason for the M2
  threshold: pushing celebrity posts is where nearly all of the write amplification comes from.
- Timings differ by a factor of about 28 between two runs of the same command while other builds
  were running, so M1 records them as single observations and not as a benchmark.
- Defects found and fixed during M1:
  - A bus test hung: it retried `Consume` until it saw `ErrGroupBusy`, but when its own retry won the
    race it blocked forever. Root cause: the test raced with the consumer start. Fix: wait until the
    group is active, then call once.
  - govulncheck reported GO-2026-6809 as reachable through the Valkey client's TLS code (ADR 0003).
- Graph realism: the tail exponent of about 1.0 is heavier than published follower-count fits; at
  3M users, million-follower accounts force half the users to follow the top account (RFC risks).

## Improve

- Chunked two-stage fan-out (ADR 0002) spreads one celebrity post over 16 partitions and 8 writers
  (the three celebrity posts became 3,490 tasks).
- The own RESP2 client (ADR 0003) removed the reachable crypto/x509 path from the Valkey adapter.

## Control

- CI (`.github/workflows/ci.yml`): gofmt, `go vet` (with and without the integration tag),
  `go test -race`, `scripts/vulncheck.sh`; a second job starts Kafka 4.1.0 and Valkey 8.1.4 as
  service containers (digest-pinned, localhost only, memory-capped), runs `TestKafkaAndValkeyEndToEnd`
  and the demo on a 50,000-user graph, and prints the `verify:` line as a `::notice`.
- Tests hold the CTQs: oracle and redelivery tests (no loss, no duplicates), graph-shape test,
  malformed-input tests and two fuzz targets.

## Verified only in CI, or not yet

- **CI-only, first CI run pending:** the Kafka and Valkey path (`TestKafkaAndValkeyEndToEnd`, the
  `e2e` job). No Docker was used locally; there are no Kafka or Valkey numbers yet.
- **Race detector:** `go test -race` needs cgo and there is no C compiler on this machine, so `-race`
  runs only in CI.
- **govulncheck:** with Go 1.26.9 it reported GO-2026-6809 (crypto/x509, fixed in Go 1.26.10),
  reachable through franz-go's optional TLS dialer, which this code never configures, and
  `scripts/vulncheck.sh` allowed that one ID. With Go 1.26.10 (2026-10-30) it reports no
  vulnerabilities and the allowlist is removed (see Maintenance 2026-10-30).
- **Not measured:** read latency, Valkey memory, pull and hybrid strategies (M2, M3).
